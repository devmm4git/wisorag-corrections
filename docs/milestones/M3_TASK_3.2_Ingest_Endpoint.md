## Objective

Implement `POST /corrective-actions/ingest` in FastAPI.
Receives a new corrective action from WISOHUB, validates it (L1/L2/L3),
generates a 768-dim embedding via Vertex AI `text-embedding-004`, and
inserts it into AlloyDB — available for RAG retrieval in < 30 seconds.

## Validation Levels

| Level | Fields | HTTP Behavior |
|-------|--------|---------------|
| **L1 — Hard reject** | `concern_id`, `concern_description`, `corrective_action` | 400 Bad Request |
| **L2 — Silent warning** | `department`, `product_line` | 201 Created — record enters but won't appear in hard-filter retrieval. Internal logs only. |
| **L3 — Silent info** | `plant`, `severity`, `collection_point`, `charged_zone`, `resolution_time_min` | 201 Created — stored as NULL. Internal logs only. |
| **BigQuery only** | `coach_cds_id`, `vin_number` | Never written to AlloyDB — routed to BigQuery feedback_log |

## HTTP Status Codes

| Code | error_code | Condition |
|------|-----------|-----------|
| `201 Created` | — | Record embedded and inserted into AlloyDB |
| `400 Bad Request` | `Missing required field: 'X'` | L1 field missing or empty |
| `400 Bad Request` | `Text too short: N words, N chars` | corrective_action < 5 words or < 30 chars |
| `409 Conflict` | `Record already exists in AlloyDB` | Duplicate concern_id — idempotent |
| `422 Unprocessable` | `AI quality check failed: ...` | AI validator rejects semantic quality |
| `500 Internal Error` | `Embedding generation failed: ...` | Vertex AI timeout or failure |
| `500 Internal Error` | `AlloyDB insert failed: ...` | INSERT into corrective_actions_vectors failed |

## Backend Flow

```
WISOHUB → POST /corrective-actions/ingest
    ↓
CorrectiveActionRequest (Pydantic — L1 validation)
    ↓
sync_new_corrective_action() — backend/pipelines/sync_new_ca.py  [M2 — DO NOT MODIFY]
    ↓
Vertex AI text-embedding-004 (768 dims — IMMUTABLE)
    ↓
INSERT INTO corrective_actions_vectors
    ↓
coach_cds_id + vin_number → BigQuery feedback_log
    ↓
201 Created
{ success, concern_id, alloydb_id, embedding_dims, latency_ms, message }
```

## Key Constraints

- `sync_new_corrective_action()` from M2 is the backend — NOT modified
- `resolution_time_min` maps to `mttr_minutes` in AlloyDB
- `coach_cds_id` and `vin_number` go to BigQuery ONLY — never to AlloyDB
- Embedding model: `text-embedding-004` — 768 dims — IMMUTABLE
- Swagger auto-generated by FastAPI from Pydantic models
